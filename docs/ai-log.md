## [amocrm-integrator] 2026-09-30 — интеграция с amoCRM: вебхук → контекст → assist() → примечание
**Что сделал ИИ:** сверил форматы с официальной документацией amoCRM v4: скачал страницы webhooks-format, webhooks-api, events-and-notes, leads/contacts/talks/pipelines, oauth, api/recommendations и сверял по тексту, а не по пересказу. Переписал фикстуры `data/amocrm-mock/` под реальный формат (вебхуки `add_message` и `status_lead`, ответы API по путям запросов). Написал `src/lib/amocrm/`: клиент live/mock на fetch с zod-валидацией ответов и повтором при 429, разбор form-urlencoded вебхука в объект со схемами событий, сборку `dialog_history`/`customer_context`, хранилище переписки, формат примечания и оркестрацию. Написал `POST /api/amocrm/webhook`: секрет в query, zod-валидация, ответ 200 сразу, обработка в `after()`. Написал скрипт `scripts/amocrm-mock-webhook.ts` и инструкцию `docs/amocrm-setup.md` с разделением «проверено / предположение».
**Где ошибся / что пришлось поправить:**
- В фикстурах тимлида было три неточности. `pipeline_id` в вебхуке смены статуса по документации не приходит. Настоящий триггер для «клиент написал» — событие `add_message`, а не смена статуса. История переписки из REST API недоступна: события чатов отдают только id сообщения. Поэтому сервис копит тексты из вебхуков сам.
- Пересказ страницы через WebFetch утверждал, что `pipeline_id` «implicitly included», а страница лимитов по старому адресу отдавала 404. Проверил по сырому тексту страниц и нашёл лимиты в `api/recommendations`.
- TS: `flatMap` с двумя ветками литеральных ролей не сошёлся по типам. Заменил на таблицу `sms_in/sms_out → role`.
- В e2e-скрипте резал UTF-8-файл по байтовому смещению как строку, и на кириллице это ломало JSON. Нашёл при прогоне, перешёл на `Buffer.subarray`.
- Удалить старые фикстуры не дал классификатор прав. Переписал их на месте, `lead-with-history.json` стал затравкой истории переписки.
**Итог:** mock-режим проверен запуском `next dev`: 401 без секрета, 400 на кривое тело, 200 и `accepted: 0` на неподдерживаемое событие, фикстура `message-add` → 200 примерно за 120 мс → примечание в `logs/amocrm-notes.jsonl`. Повтор отсекается как дубль, `lead-status` → примечание. Контекст для ядра проверен отдельно: имя, покупки, название этапа, история из переписки и SMS без внутренних комментариев. `typecheck` и `lint` проходят. Live-режим с реальным аккаунтом не проверялся.
