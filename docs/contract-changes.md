# Предложения по изменению контрактов

Агенты **не меняют** `src/lib/contracts.ts` и формат `data/kb/` сами. Предложение пишется сюда, тимлид принимает или отклоняет.

```
## ГГГГ-ММ-ДД [роль] — краткое название
**Что изменить:** поле/схема
**Зачем:** ...
**Кого затрагивает:** backend / frontend / amocrm / eval
**Статус:** предложено | принято | отклонено (причина)
```

---

## 2026-09-30 [prompt-engineer] — `upsell.rule_id`
**Что изменить:** `UpsellSchema` — добавить `rule_id: z.string().optional()` (id правила из `upsell-matrix.json`, заполняется при `recommended: true`).
**Зачем:** сейчас «допродажа только из матрицы» проверяется лишь по `product_id`, хотя один товар может предлагаться по разным правилам. С `rule_id` QA проверит, что сработавшее правило действительно подходит (триггер, intent, `exclude_if`), а менеджер увидит, откуда взялась подсказка.
**Кого затрагивает:** backend (схема для generateObject), frontend (можно показать), eval.
**Статус:** предложено

## 2026-09-30 [prompt-engineer] — ссылки на политики в `sources`
**Что изменить:** ничего в `contracts.ts`. Договорённость для backend: политики, которые подмешиваются всегда, передавать ещё и чанками `policy:*` в `chunks` (или вместо строки `policies`).
**Зачем:** `sources` принимает только id чанков. Блок `<policies>` приходит сплошным текстом без id, поэтому ответ о доставке или оплате нельзя подтвердить источником, даже если он верный.
**Кого затрагивает:** backend, eval.
**Статус:** предложено

## 2026-09-30 [prompt-engineer] — `SystemPromptInput`: к сведению (сигнатура не сломана)
**Что изменить:** уже сделано в зоне prompt-engineer, только необязательные поля. Добавлено `catalog?: string` («id | название | категория» по строке на товар). `customer` помечен `@deprecated` и в system не выводится: контекст клиента передаётся через `buildUserMessage(req)`.
**Зачем:** без каталога модели неоткуда взять `upsell.product_name` и понять, что лежит в `past_purchases`.
**Кого затрагивает:** backend (рекомендуется передавать `catalog`, собранный из `products.json`).
**Статус:** предложено

## 2026-09-30 [prompt-engineer] — поле для рассуждения (на будущее)
**Что изменить:** если eval покажет ошибки в intent или в допродаже, добавить в начало `AssistResponseSchema` поле `reasoning_brief: z.string()` (1–2 предложения, клиенту не показывается).
**Зачем:** в JSON поля генерируются по порядку. Без такого поля модель пишет `client_reply` раньше, чем явно определила intent и тон.
**Кого затрагивает:** backend, frontend (скрыть), eval.
**Статус:** предложено (отложено до результатов eval)
