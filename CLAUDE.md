# Проект: ИИ-ассистент менеджера O-complex (тестовое задание)

## Задача
Сервис принимает обращение клиента, сверяется с короткой базой знаний и выдаёт два блока:
1. вежливый ответ клиенту;
2. подсказку менеджеру по допродаже на основе контекста диалога в amoCRM.

Сдача: видео 1–2 минуты с демонстрацией и рассказом об использованных ИИ-инструментах.
Компания: O-complex, продукты для здоровья и бережного очищения организма.

## Стек (не менять без согласования)
- TypeScript (strict), Node.js актуальной LTS
- Next.js (App Router), текущая стабильная версия
- Vercel AI SDK (`ai`) + провайдер модели + `zod`, структурированный вывод через `generateObject`
- Эмбеддинги через API; векторный поиск в памяти (cosine, top-k)
- React + Tailwind (+ shadcn/ui) для UI
- amoCRM REST API v4 через `fetch`, без сторонних SDK
- Версии пакетов проверять через `npm view <пакет> version`, не угадывать

## Контракты (единый источник правды)
- `src/lib/contracts.ts` — zod-схемы запроса и ответа. Менять **только** через тимлида.
- `data/kb/` — база знаний, формат описан в `data/kb/README.md`.
- Любой агент, которому нужно изменить контракт, не меняет его сам, а пишет предложение в `docs/contract-changes.md`.

## Структура
```
data/kb/            база знаний (products.json, upsell-matrix.json, faq.md, policies.md)
data/eval/          тестовые обращения и эталоны
src/lib/            contracts, retrieval, llm, amocrm, prompts
src/app/api/        эндпоинты (/api/assist, /api/amocrm/webhook)
src/app/            демо-UI
scripts/            eval-скрипты, сборка индекса
docs/               ai-log.md, решения, отчёты
```

## Правила домена (критично)
- Не ставить диагнозов, не обещать лечебного эффекта, не давать медицинских рекомендаций.
- Вопросы о противопоказаниях, беременности, детях, хронических заболеваниях: отвечать строго по базе, советовать консультацию врача, ставить `needs_human: true`.
- Если ответа нет в базе, не выдумывать: вежливо сказать, что менеджер уточнит, и поставить `needs_human: true`.
- Допродажи только из `upsell-matrix.json`. Не предлагать допродажу раздражённому клиенту или при жалобе.
- Не придумывать факты о компании, товарах, ценах и условиях. Всё, что не подтверждено источником, помечать как `TODO: проверить`.

## Правила работы агентов
- Работать только в своей зоне файлов (указана в описании роли).
- Маленькие осмысленные коммиты: `<роль>: <что сделано>`.
- Секреты только в `.env.local`, в репозиторий попадает `.env.example`.
- После завершения задачи **обязательно** дописать в `docs/ai-log.md` запись:
  `## [роль] дата — задача / что сделал ИИ / где ошибся или что пришлось поправить / итог`
- Перед тем как объявить задачу выполненной: `npm run typecheck` и `npm run lint` проходят, результат проверен запуском, а не на глаз.
